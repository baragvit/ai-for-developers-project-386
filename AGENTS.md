# AGENTS.md

Hexlet project «Запись на звонок» (Cal.com-like booking, no auth). See README.md for the product rules.

## Design First

- The HTTP contract in `api-contract/main.tsp` (TypeSpec) is the single source of truth for frontend and backend.
- When behavior changes: edit the contract first, run `npm run contract` (same as `make contract` / `mise run contract`), then update both sides.
- `npm run contract` writes these generated paths. Never edit them by hand; `mise run contract:check` regenerates them and fails if they differ from git (untracked output included):
  - `api-contract/openapi.yaml` — OpenAPI from TypeSpec.
  - `frontend/src/api/schema.d.ts` — client types for `openapi-fetch` (`openapi-typescript`).
  - `backend/src/api/model/schema.d.ts` — backend DTO types (`openapi-typescript`).
  - `backend/src/api/model/zod/` — backend zod request schemas (`@hey-api/openapi-ts`, exact version pinned, config in `backend/openapi-ts.config.ts`).
- Backend request validation uses the generated zod schemas; `backend/src/api/validation.ts` only adds `.trim()` and Russian messages (zod global error map).
- The frontend reaches the API only through `frontend/src/api`; oxlint forbids `fetch`, `XMLHttpRequest` and `openapi-fetch` elsewhere.
- Backend API tests call `injectChecked` (`backend/test/contract.ts`): every response is validated against `api-contract/openapi.yaml` by operation and status.

## Layout

- `frontend/` — React + Vite + Tailwind + shadcn/ui (`src/components/ui` is generated by the shadcn CLI). API access only through `src/api/client.ts` / `src/api/queries.ts`.
- `backend/` — Fastify. Layers:
  - `src/api/` — routes, request validation (generated zod schemas), DTO ↔ domain mappers. DTO types come from `src/api/model`.
  - `src/services/` — business logic. Takes and returns primitives, domain types (`src/domain/model.ts`) or `Result`; never API DTOs.
  - `src/domain/` — domain types, `Result`, slot generation (pure functions).
  - `src/storage/` — repositories (in-memory).
- `e2e/` — Playwright scenarios against the production build.

## Commands

Tool versions are pinned in `mise.toml`.

```bash
mise install && mise run install
npm run contract      # TypeSpec -> OpenAPI -> TS types
npm run mock          # Prism mock on :4010
npm run dev:backend   # :7341
npm run dev:frontend  # :5391, proxies /api to API_PROXY_TARGET (default :7341)
mise run check        # contract up to date, lint, typecheck, unit tests, e2e — same command as CI
```

## Conventions

- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `test:`, `ci:`, `build:`, `chore:`, optional scope, e.g. `feat(backend): reject overlapping bookings`.
- An implementation commit references the GitHub issue it implements in the subject, e.g. `feat(backend): reject overlapping bookings (#18)`. GitHub turns `#18` into a link, so the history shows which commit did which ticket.
- `.github/workflows/hexlet-check.yml` is generated by Hexlet: never edit, rename or delete it.
- UI copy is in Russian; code, identifiers and comments are in English.
- Times travel over the API as ISO 8601 UTC; the frontend renders them in the viewer's time zone, the backend computes working hours in the owner's time zone.
- Business rule to keep covered by tests: two bookings can never overlap, even for different event types.
